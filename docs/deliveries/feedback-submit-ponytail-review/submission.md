# 验收反馈与项目提交审查

修复了三种在隔离环境中可重复触发的提交或回执故障，以及一种可独立触发的 Orca worker 事件积压。源码基线为 `5ad219b`，按同一主人、多项目并行及少量工作间连接审查。

指定的本机入口为 `node C:/Users/Alaya/AppData/Roaming/orca/agentboat-current/coordinator/scripts/client.mjs`。只读核对发现，Orca 当前运行的是开发插件 v0.1.55，稳定入口的目录指针仍指向正式 v0.1.52。该入口通过本机桥接向运行中的 worker 发请求。现有 v0.1.55 候选 `25ee939` 的 CLI 请求与桥接脚本和本次源码基线相同。发布或现场回验时应记清两侧版本。

## 已修复

1. **后台通知改变了提交使用的项目版本。** 条件是面板或 CLI 读到项目版本后，上一条普通通知刚好从待发变为发送中、已发送或待核对。基线隔离测试中，原验收仍待处理，空留言通过仍被拒绝为「项目已更新」。普通投递状态继续串行落盘，项目内容版本只随真实内容变动推进。接管控制通知、项目级版本校验、逐项校验和同编号回放仍走原路径。测试确认原反馈成功、旧项目版本的新请求被拒、原编号重放仅留一条历史。 [worker.ts](../../../coordinator/src/worker.ts#L680) [store.ts](../../../coordinator/src/store.ts#L226) [回归](../../../coordinator/src/coordinator.test.ts#L293)
2. **项目报告已入账，CLI 仍可能返回失败。** 条件是 `project.agent submit` 写入后，组装回执时重新读取的项目目录已变。隔离 CLI 通过原 HTTP 桥接复现了「项目已从 Orca 移除或不在工作间项目列表」，当时待验收项已保存。CLI 从已提交快照及写入前验证过的项目引用构造回执。客户端仍核验原请求编号和指纹，归档任务仍从原归档取提交摘要。面板读取和项目绑定继续返回原有导航信息。 [worker.ts](../../../coordinator/src/worker.ts#L1123) [client.mjs](../../../coordinator/scripts/client.mjs#L160) [真实 CLI 入口的隔离回归](../../../coordinator/src/coordinator.test.ts#L317)
3. **主动连接方向的跨工作间反馈等待普通同步。** 条件是发起连接一侧的普通报告仍在采集，同时用户提交验收反馈。基线在隔离回环中超过 3 秒仍无回执，放开报告后才能继续。使用已有轻量同步优先发反馈，若轻量同步结束时该请求仍未发出，保留原普通同步入口。原请求已发出的结果不明时继续走原编号核对。对端开放权限、单连接在途限制、项目版本、附件校验与历史保持原有约束。 [links.ts](../../../coordinator/src/links.ts#L632) [回环回归](../../../coordinator/src/links.test.ts#L282)
4. **状态事件可能积压到 Orca 强制停止 worker。** 本机 Orca 宿主代码最多保留 64 条未回执事件，达到上限时终止插件 worker。worker 宿主会等异步事件处理结束才回执。原 AgentBoat 状态监听把合并等待、读 agent 和退避也放在该 Promise 中。隔离测试中送入 65 次状态变化时，原事件先等一次采样才全部回执。把采样留在既有后台调度，事件回执立即返回。测试确认 65 次事件都先回执，仍只采样一次，并保留读中再收到变化时的重采样。代码和宿主机制足以确认这条独立路径，现有单次日志缺少与具体提交相同的请求编号和时间线。 [worker.ts](../../../coordinator/src/worker.ts#L156) [事件回归](../../../coordinator/src/agents.test.ts#L268)

## 提交条件与剩余范围

- **面板用户反馈。** 草稿先保存，底栏只计当前有效选择。通过留言可空，修改意见、受阻备注及「其他」决定按原规则必填。面板先保存批次和原请求，再发请求。只有同一请求的匹配写入凭证才能清除选中草稿。对端报告显示事项消失时，仍须核对原回执。旧草稿及附件的证据沿用既有交付。 [必填提示](../feedback-missing-field-location/report.md) [旧草稿](../feedback-dock-stale-draft/report.md) [面板提交](../../../coordinator/src/panel-page.ts#L1190)
- **项目主会话发布报告。** `client.mjs submit` 新增或修改项目任务、成果和待验收项。新任务需要标题、目标和有效阶段。验收需要引用本任务已登记成果，有变化才开启下一版。仍有待决定、待验收或需修改时，不能直接标记完成。关联原 Orca 业务决定还须核对来源会话、Run、Task 和 Dispatch。执行者的 `worker_done` 是 Run 邮件，项目主会话处理后才会产生项目提交。 [桥接说明](../../../coordinator/skill/orca-project-coordinator/references/bridge.md#项目主-agent) [存储校验](../../../coordinator/src/store.ts#L271)
- **Parking v12 的入账和界面残留。** 既有记录里出现过一次已入账但界面仍显示。面板代码有一条对应的可能路径：本地写入后若回执中断，会保留原请求并等待「核对提交」，此时可看到草稿。另一个可见时序是提交期间忽略项目变更事件，成功后即时快照只刷新本批项目。若另一个项目在这段时间更新且之后没有变更事件，它会显示上次读到的状态。最小后续办法是记录提交期间尚未被回执覆盖的项目变更，批次结束后合并刷新一次。现场缺少原请求编号、接口错误和面板事件时间线，暂不能判断 Parking 走了哪条路径。 [写入凭证与核对](../../../coordinator/src/panel-page.ts#L1224) [事件订阅](../../../coordinator/src/panel-page.ts#L1908)
- **CLI 跨会话重放。** 原文件里的请求编号相同，但 CLI 可能依当前会话或 `run-current` 结果补入不同的身份字段。若前一次已入账，第二次的整个输入指纹会不同，存储层会拒绝复用该编号。精确相同的请求仍可重放。若需支持跨会话重放，先定义普通提交的稳定指纹字段并保留历史凭证读取，关联原问题仍按当前授权核对。 [身份补入](../../../coordinator/scripts/client.mjs#L68) [请求回放](../../../coordinator/src/store.ts#L226)
