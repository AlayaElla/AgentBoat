# AgentBoat v0.1.50 全插件 Ponytail Review

## 需修复

1. **回复飞书旧提醒可以给已经补充过成果的决定写答案**。`coordinator/src/store.ts:69-72,337-358,432-439`，`coordinator/src/feishu.ts:65-83`，`coordinator/src/worker.ts:567-598`。
   - 触发条件。先发带选项的飞书决定提醒，再通过 `submit` 给同一未结决定更换或补充关联成果。此前已经关联原生 Orca 问题的决定另有冻结校验。主人直接引用旧飞书提醒回复。
   - 影响。`submit` 更新该决定的 `presentedAt`，飞书提醒仍以任务、决定编号和固定版本 `1` 标识。决定内容指纹只含问题与选项。旧提醒会被当成原引用命中，`feedback` 校验继续通过，答复写入当前卡，插件回执显示已记录。历史验收的版本保护和面板按项目 revision 提交的路径仍有各自校验。
   - 最小修法。让飞书决定提醒随决定呈现版本记录并核对 `presentedAt` 或等价的绑定凭证，维持同一决定编号。对旧库里的未带版本凭证回执，按决定是否曾更新判断能否安全匹配。补一条先发提醒、再更新成果、最后回复旧提醒的端到端模拟测试。

2. **单个外部连接的坏记录可阻断工作间启动**。`coordinator/src/connections.ts:19-25,92`，`coordinator/src/butler.ts:48-52,225-235`，`coordinator/src/worker.ts:1291-1317,1342-1356`。
   - 触发条件。外部连接目录可读，其中一条 A2A 连接的持久化记录版本或形状不兼容。启动时 `connections.start()` 逐条等待 `Butler.start()` 读取记录。
   - 影响。该读取抛错会提前退出整个 `coordinator.start()`。稳定 CLI 监听在它之后，主会话恢复、未确认通知与飞书恢复也排在后面。项目数据可能完整，但稳定入口拿不到本次启动回执，工作间核心流程停在启动阶段。已有目录形状校验本身有保存旧数据的价值。
   - 最小修法。按连接隔离启动和列表读取错误，报告有问题的连接，保留其记录，再让其余连接和工作间恢复继续。用隔离存储加一份不兼容记录及一个正常连接，确认概览和 CLI 可以继续使用。

3. **工作间接管正文重复整段职责说明**。`coordinator/src/role-registry.ts:7-12`，`coordinator/src/main-agent.ts:115,281-297`，`coordinator/src/backup-lead.ts:427-428,488-504`，`workspace/skill/agentboat-workspace/SKILL.md:8-24`。

## 结论

本次减冗可供合包审阅。产品复审发现的两处行为缺陷需分别修复，尤其是飞书旧提醒写回的决定版本边界。本次提交落实条目 3–7。工作间公共接管提示从 343 字符减至 200 字符，保留接管自查明确依赖的 `client.mjs message` 指令；项目送达末尾的提示逐字比对一致。
