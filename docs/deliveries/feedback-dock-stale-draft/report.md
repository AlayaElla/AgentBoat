# 验收底栏旧草稿修复

截图中，Parking_Loop 的胜利结算第 7 版选了「结算设计继续调整」，并带有一张图。底栏显示 2 条，批次因为另一项验收已经更新、退出待验收状态而被拒绝。

隔离面板复现了同项目的同类问题。新勾选一项时，修复前按钮显示 `提交 2 条`，请求含旧验收和新验收两项。修复后显示 `提交 1 条`，请求只含新验收，旧草稿的文字和附件保持原样。展开底栏的「保留草稿」可查看、预览附件或移除旧稿。重新选择新版时会新建草稿。

底栏和提交共用当前待处理项及版本校验。离线或待同步的对端草稿会保留。对端报告中事项消失后，待核对批次继续使用原请求编号、内容和签名，收到匹配写入凭证后才清理已提交的草稿。项目级并发校验和后端版本校验仍在请求路径上。

## 验证

- `PANEL_ATTACHMENTS_ONLY=1 node coordinator/scripts/panel-browser.mjs` 跑通新增三项隔离回归和原附件回归，覆盖宽、窄面板及旧附件预览。
- 额外 21 项已有面板用例通过，覆盖多面板竞争、实时版本变化、同连接依次提交、部分失败和原批次回执。
- `npm run typecheck` 通过。隔离工作器和回环链路的 6 项定向测试通过，包含旧草稿附件读取、项目批次原子性和轻量回执。

## 真实面板回验

实际入口由协调者交接。可在测试项目保留一条验收意见和附件，再将该事项改版或退出待验收。刷新或切换页面后，只勾选另一项，确认底栏显示 `提交 1 条`，展开「保留草稿」可查看旧稿。提交后核对新事项入账，旧稿仍可查看。当前证据来自隔离面板和本机回环，真实 Parking 数据未写入，正式插件未重载。
