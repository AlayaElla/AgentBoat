# 反馈附件第 2 版验收候选

对应原验收 `verify-acceptance-feedback-attachments` 第 1 版的反馈 `msg_9896f50f23ba`。专属工作树从干净的 `1e9eef664ec04b5d91a3766b23168cd9013ba758` 开始。

## 面板

在「等你处理」选定决定选项后，可向补充说明拖入或粘贴文件。选「其他」时，自定义答案和补充说明共用一份附件列表。相同文件名与内容只保留一份，草稿重开后可按文件名移除。验收的「通过」和「需要修改」留言使用同一个入口。文本粘贴交给输入框，文件由已有的 Orca HTML 面板桥上传。

## 记录与通知

- 决定附件与答案和补充说明一同入账。提交核对题目和选项指纹、当前呈现和决定版本。任务详情的「记录」定位原决定，可预览或保存文件。
- 原项目 Run 通知包含附件列表及查询入口。已关联的 Orca 原问题继续由 `reply-decision` 回复，答复附带文件名和编号。绑定的项目主会话可通过稳定入口运行 `feedback-file <项目编号> <任务编号> <决定编号> 1 <附件编号> --decision`。验收附件继续按原参数和原存储键读取。
- 跨工作间沿用原委托反馈回执和权限。能处理决定附件的对端会声明对应能力，只支持验收附件的对端仍可处理验收附件。带附件的反馈超过已有同步限额或对端能力不足时会整条拒绝，草稿保留。跨工作间附件每批最多 96 KiB。

## 隔离验证

- 360px Edge 无头测试在同一夹具覆盖决定与验收。验收粘贴 PNG、切换「通过」后拖入 TXT，再提交需要修改的留言。决定先在选项补充说明粘贴 PNG，再切换自定义答案拖入 TXT，重复粘贴只上传一次。测试核对两个编辑区使用相同入口、合成文字粘贴未被拦截、重开草稿可键盘移除测试文件，提交后重新打开两处历史可预览，TXT 可保存。页面错误和外部网络请求均为零。 [面板用例](../../../coordinator/scripts/panel-browser.mjs) · [窄面板预览](decision-feedback-360.png)
- 4 项 Worker 与回环用例通过。决定的过期呈现和错误指纹被拒绝，原 Run 收到带原问题与附件的通知，重复提交只记录一次。重启后绑定主会话可读出原文件，其他会话被拒绝。使用第 1 版原存储键预置的验收附件仍可读，且不会在决定记录中打开。 [Worker 用例](../../../coordinator/src/coordinator.test.ts) · [委托用例](../../../coordinator/src/links.test.ts)
- 2 项隔离 CLI 用例通过。旧验收查询与决定查询传入各自范围，带附件的 `reply-decision` 仍取得原问题线程回执。类型检查、构建及 Orca 1.4.278 本地插件校验均通过。 [CLI 用例](../../../coordinator/scripts/client.test.mjs)

## 候选安装后的实机核对

在一条待决定选「其他」，向答案拖入文本文件，向补充说明粘贴截图。移除一份多余文件并提交，重开任务记录预览，再从已绑定项目主会话核对原问题答复及附件定位。用一条待验收的「通过」或「需要修改」留言再试一次拖入或粘贴。

实机剪贴板、桌面拖放、原 Run 的实际收件和实机对端由协调者在候选安装后核对。本次验证使用假宿主、无头面板和本机回环，候选尚未替换正式插件。
