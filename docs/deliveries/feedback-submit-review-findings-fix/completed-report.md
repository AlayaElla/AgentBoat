# 已结束执行者的回报提醒

回报发送超过 30 分钟且不超过 24 小时、成果仍未登记时，项目主会话可以收到「执行者回报待提交」。提醒沿用项目 Run 邮箱和现有去重记录。首次尝试两小时后仍待登记时，工作间主会话最多收到一次升级提醒。当前任务和已归档任务的提交凭证都能取消待登记提醒。普通未回复问题继续要求派工和任务处于活跃状态。

成功回报须与同一 Run 内已完成的 Task 和 Dispatch，以及成功的 worker 相符。Orca Task 的原始完成结果须记录该封邮件和它的发送者。发送者无法从 worker 列表核对时，读取该 Dispatch 的原始指派记录。失败或被 Orca 拒绝的回报，以及冒用其他 Run、Task、Dispatch 或发送者的邮件，均不会进入待登记提醒。

## 验证

- 只读检查 AgentBoat 项目 Run 的 35 条原生成功回报，均与 `succeeded` worker、`completed` Dispatch、`completed` Task 及 Task 完成凭证匹配。其中 21 条保有 worker 列表句柄，14 条没有该句柄。各选一条回放，实际时钟下两条均已超过时间窗口。将时钟移到各自回报后 30 分钟零 1 毫秒，两条均进入提醒候选，缺句柄的一条通过 `worker-show` 核对了原始指派。只读回放未发送邮件。
- `npm run typecheck` 通过。四项隔离回归通过，覆盖普通问题及真实回复、成功回报真伪与时间边界、项目提醒和升级去重、当前与已归档提交抑制提醒。隔离测试通过 `OrcaRuntime.mail` 读取模拟宿主响应，并使用真实归档写入和读回。
- 连接隔离子工作树也修改了 `coordinator.test.ts`。该分支新增启动及目录用例，本分支修改文件前段两项 Run 邮件用例，差异位于不同位置。`worker.ts` 由连接隔离分支修改。

正式环境仍待用已安装版本验证新的真实回报从项目 Run 邮箱进入面板，随后由提交清除。此次未安装或发布插件、发送真实提醒或操作用户 hooks。
